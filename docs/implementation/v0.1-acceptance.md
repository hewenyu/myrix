## 已解决的关键验收缺陷

- 恢复必须根据当前数据库权限与 boot 证明显式签发 resume，不能信任磁盘头或放宽 driver 主体校验；实际重启已通过。恢复使用状况改为单条有界 SQL、同一 MVCC 快照，修复并发时误分配两枚 resume 的问题。读取故障及终止恢复结果保持 fail-closed，并延后原命令、返还投递尝试预算，不能落入裸 POST。详见 [恢复 ADR](<../adr/0028-runtime-session-recovery.md>) 与 25 个恢复回归。
- React 使用提交后的代际归属，冻结 mutation 的作品/章节目标；迟到回包、放弃的并发渲染、A→B→A、卸载和旧选择回调不能跨对象写入。
- 旧 GET、迟到保存确认不能回退已知版本；保存期间继续输入不会被覆盖。缓存失效保留 TanStack 的前缀语义，另有目标 query-state 断言。
- 使用 commandId 消除极快持久用户回显与本地 pending 的重复；持久终态刷新业务数据而不是把助手正文当作编辑器内容。这些均已通过最终浏览器断言。

## 明确边界与后续工作

- **这是本地开发栈首版**。生产 OIDC、真实 Kubernetes/RWO 卷故障迁移、P3 大规模并发/隔离验收、P8 升级回放及可发布容器镜像未在本轮验收；不能用单测或本地浏览器替代。
- 安装的 DSH `0.2.0-rc.2` npm 产物与只读 vendor 版本相符，不等于已证明该产物来自 vendor 的具体源码提交。
- 章节上下文仍是显式复制后提交；未保存草稿不会自动发送，须先保存，切换对象后重新复制。剪贴板不可用时提供手动选择路径。
- 浏览器 EventSource 不提供失败响应的 HTTP 状态，因此目前不能显示精确的终止恢复原因；服务端仍拒绝不合法恢复，没有授权旁路。模型配置徽标也只表示前端实际观测，不等价于网关密钥探测。
- 前端主 chunk 的大小警告仍在，后续可优化分包；不影响本轮构建和功能通过。
- 报告与测试作品保留供人工检查。运行产物位于忽略目录，不纳入源码分发，私有配置不包含在证据中。
